# ADR-0003 — کارِ چندنفره روی یک سرویسِ زنده

- وضعیت: پذیرفته
- تاریخ: 2026-11-04

## شاخه و بازبینی

- **trunk-based**: `main` همیشه قابلِ استقرار؛ شاخه‌های کوتاهِ `feat/…`, `fix/…`.
- PR اجباری برای `main`، حداقل یک بازبینی، و **همهٔ گیت‌های CI سبز**.
- `CODEOWNERS`: هر تغییر در `infra/` و `.github/` نیازمند بازبینیِ مالکِ زیرساخت است.
- commit پیام‌ها توضیحِ «چرا» می‌دهند، نه «چه».

## گیت‌های CI

1. تستِ واحدِ پنل.
2. `check-no-secrets` (الگوهای کلید/توکن روی همهٔ فایل‌های tracked).
3. `ansible-playbook --syntax-check` و `ansible-lint`.
4. ساختِ آرشیو/باینری (بعداً: امضای ریلیز).

## سکرت‌ها

- **در ریپو هیچ سکرتی نیست.** محلی: Ansible Vault. CI/CD: GitHub Environments.
- کلیدِ امضای ریلیز فقط در CI (Environment `production`) است، نه روی لپ‌تاپ.
- با اضافه‌شدن هر عضو تیم: **چرخشِ کامل** — توکن Cloudflare، کلیدهای SSH، `.env` سرویس،
  کلیدِ امضا، و رمزِ دیتابیس. چک‌لیست در `SECURITY.md`.
- هر سکرتی که یک بار در یک کانفیگِ دستی بوده، دیگر «محرمانه» نیست؛ در اولین استقرار v2 چرخانده می‌شود.

## کارِ هم‌زمان روی سرور

- هیچ‌کس SSH نمی‌زند و کانفیگ را ادیت نمی‌کند؛ تغییر = PR روی `infra/` → CI → استقرار.
- کارهای هم‌زمان با «قفلِ استقرار» هماهنگ می‌شوند: یک Environment در GitHub در هر لحظه فقط
  یک استقرار فعال دارد (`concurrency: deploy-<env>`).
- انحرافِ باکس با `make drift ENV=prod` (یعنی `ansible --check --diff`) هر شب در CI بررسی می‌شود.
