# ADR-0004 — کانتینر برای هر محیط، روی دو هاستِ جدا

- وضعیت: پذیرفته
- تاریخ: 2026-11-07

## تصمیم

- **دو ایمیج**: `panel` (Node 22) و `xray` (باینریِ pin‌شده با checksum).
- **دو استقرارِ مستقل**: `stage` روی باکس خودش، `prod` روی باکس خودش. «دو کانتینر روی یک باکس»
  جداسازی نیست — یک `sysctl` یا یک پورت می‌تواند هر دو را با هم ببرد.
- هر دو سرویس با **`network_mode: host`** اجرا می‌شوند:
  - کور: UDP/mKCP نباید NAT ببیند، و پورت‌مپِ UDP منبعِ کلاسیکِ دردسر است.
  - پنل: باید روی `127.0.0.1` به admin API کور برسد و **از بیرون دیده نشود**.
  - TLS و HTTP عمومی روی nginx خودِ هاست می‌ماند (همان شکلِ v1).
- `read_only` + `no-new-privileges` + `tmpfs` برای هر دو، و لاگِ محدود.
- ایمیج‌ها در **GHCR** با تگِ commit SHA؛ استقرار با تگ، نه با `latest`.

## چه چیزی در کانتینر نیست

- **BBR و `fq`**: ویژگیِ کرنل‌اند؛ نقشِ `base` آن را ست و assert می‌کند.
- **nginx/certbot**: روی هاست.
- **دیتابیس**: در برشِ S2 به‌صورت volume یا سرویسِ جدا تصمیم می‌شود.

## استقرار

`workflow_dispatch` با ورودیِ محیط و تگ، روی Environment متناظر (تأییدِ دستی برای prod)،
`concurrency: deploy-<env>` تا دو نفر هم‌زمان در یک محیط استقرار ندهند. اسکریپتِ `deploy.sh` روی
باکس با `docker compose config --quiet` اعتبارسنجی و سپس تا آماده‌شدنِ `/readyz` (که یعنی admin API
کور هم جواب می‌دهد) صبر می‌کند؛ اگر نشد، لاگ می‌دهد و با کدِ خطا برمی‌گردد.

## بازگشت

تگِ قبلی = `deploy.sh <env> <previous-tag>`؛ کانفیگ قبلی = `config/xray.json` با پسوندِ backup
که نقشِ `core` در هر تغییر می‌سازد.
